# External Drive Panel

이 프로젝트는 C# / WPF(.NET 10 LTS) 기반 Windows x64 앱입니다.
MIT 라이선스로 배포합니다. 설치 프로그램과 자동 업데이트는 Velopack을 사용합니다.
설치 파일은 [GitHub Releases](https://github.com/criticalmasslab/external-drive-panel/releases/latest)에서 받을 수 있습니다.

## 설치 및 자동 업데이트

### 1.0.7 변경

- 설정에서 패널 높이를 균등 분할하거나 현재 내용에 따라 자동 배분하도록 선택합니다.
  즐겨찾기·폴더·검색 결과와 아이콘/상세 보기의 실제 행 높이를 반영하고 여백도 비례 배분합니다.
- 패널 스크롤바를 얇게 다듬고 새로 만들기 버튼을 공통 스타일의 폴더 + 아이콘으로 변경했습니다.
- 메인헤더에 외장하드 새로고침을 추가했습니다. Windows가 안전 제거 상태로 유지하는 지원 USB 저장장치는
  사용자 권한 승인 후 해당 포트의 재연결을 시도합니다. 장치에 따라 케이블을 다시 연결해야 할 수 있습니다.
- 개발용 실행본은 별도 설정과 실행 경로를 사용합니다. 개발용 자동실행 등록은 로컬 스크립트로만 선택합니다.

### 1.0.6 변경

- 상세 목록의 이름은 왼쪽, 수정 날짜·크기는 가운데, 유형은 오른쪽으로 정렬합니다. 열 제목도 동일하게 정렬합니다.
- 꺼내기는 볼륨 직접 잠금/마운트 해제 대신 Windows PnP의 안전 제거 요청을 사용합니다.
  드라이브 문자에서 물리 디스크와 제거 가능한 장치를 읽기 전용으로 매핑하고, 요청 직전 식별을 다시 확인합니다.
- 제거 준비 중 드라이브 폴링을 멈추고, 진행 중인 패널 파일 작업을 기다린 뒤 모든 패널의
  두 종류의 디렉터리 감시 핸들·검색·미리보기·용량 조회를 정리합니다. 실패하면 감시와 UI를 복구합니다.
  같은 물리 장치의 여러 파티션도 함께 제거될 수 있으므로 확인창에 안내합니다.
- 시스템/실행 파일/설정 저장 디스크, USB 허브·호스트 컨트롤러·도크와 여러 물리 디스크의 공유 부모는
  제거 대상으로 삼지 않습니다. Windows의 거부 사유(권한/열린 핸들/드라이버 등)를 구분해 표시하며
  강제 분리나 자동 권한 상승으로 우회하지 않습니다. 새 상시 폴링은 추가하지 않습니다.
- 검증은 실제 감시 핸들 정리/복구와 가짜 제거 결과를 사용합니다. 실제 하드웨어 제거는 사용자 확인이 필요합니다.
  `dotnet run --project tests/EjectSmoke -c Release -- --inspect-only`는 읽기 전용 조회만 하며 제거를 요청하지 않습니다.

### 1.0.5 변경

- 경로 표시줄 높이를 검색 박스와 동일하게 맞췄습니다. 경로를 이동해도 높이가 변하지 않습니다.
- 우하단 앞으로 버튼의 호버 확대를 20%로 높였습니다. 클릭 영역과 배경은 그대로 유지합니다.
- 설정창 하단의 빈 안내 공간을 줄이고, 저작권·버전을 헤더와 같은 남색의 얇은 띠에 표시합니다.
- 상세 목록은 진한 행·셀 테두리 대신 흰색/옅은 회청색 스트라이프로 표시합니다.
  즐겨찾기·폴더·검색에 공통 적용하며 선택과 드롭 강조는 유지합니다.
- 유형 열은 `JPG 파일` 대신 `JPG`처럼 확장자만 표시합니다.
  확장자 없는 파일과 폴더·경로 없음 표시는 유지합니다.

### 1.0.4 변경

- 미리보기 아이콘의 활성 테두리 제거(크기 유지), 앞으로 버튼의 아이콘 확대 호버,
  설정창 저작권·버전, 경로 표시줄 고정 높이를 적용했습니다.
- 트레이 → **지금 업데이트 확인**: 확인/다운로드·최신·실패·준비 상태를 표시합니다.
  자동 확인과 같은 작업을 공유하며 중복 다운로드하지 않습니다. 준비되면 기존 하단 버튼으로 설치합니다.
- 트레이 → **설정·즐겨찾기 백업**: 내보내기/가져오기/이전 정상 설정 복원.
  복원 전 확인하고 파일 작업 완료를 기다립니다. 시작프로그램 등록과 실제 파일은 변경하지 않습니다.
  백업은 드라이브 정보와 경로를 포함하므로 신뢰할 수 있는 곳에 보관하세요.
- 변경 저장 시 `%APPDATA%\ExternalDeskPanel\config.previous.json`에 이전 정상 설정 한 개를 보관합니다.
  동일한 내용은 다시 쓰지 않습니다. 손상 파일은 기존처럼 `.bak`에 보관하며 자동 복원 대신
  사용자가 이전 정상본을 선택해 복원합니다. 가져오는 JSON은 스키마 검증과 8MiB 크기 제한을 적용합니다.
- 진단 로그는 `%LOCALAPPDATA%\ExternalDeskPanel\Logs`에만 저장합니다(트레이에서 열기).
  주기적 기록/자동 전송 없이 실행·오류 등의 이벤트만 백그라운드로 쓰고 큐와 용량을 제한합니다.
  최대 512KiB × 3개이며 파일 경로/내용/예외 메시지 대신 작업 식별자·오류 종류/코드·메서드 이름만 남깁니다.

### 1.0.3 변경

- 수정 1: 패널 묶음의 사방 가장자리에 42px 깊이 × 84px 길이 이상의 클릭 가능한 공간이
  하나도 없는 상태가 0.5초 지속되면, 해당 모니터 작업영역 우하단에 앱 아이콘 버튼을 표시합니다.
  버튼만 항상 위에 표시하고, 클릭하면 패널 그룹을 올린 뒤 숨깁니다. 패널 자체는 항상 위로 고정하지 않습니다.
  창 위치/겹침을 250ms 간격으로 확인하며 화면 캡처나 파일 조회는 하지 않습니다.
  반투명·비정형 창은 사각형 근사 판정이며, UAC 보안 화면/독점 전체화면 위 표시는 보장하지 않습니다.
- 수정 2: 설정창의 본문 스크롤을 제거하고 내용에 맞춰 초기 높이를 정합니다.
  작은 작업영역이나 창 크기에서는 본문을 축소해 모든 항목과 하단 버튼을 표시합니다.
- 수정 3: 파일 미리보기 활성 상태는 하늘색 배경·녹색 산·오렌지색 해의 벡터 아이콘으로 표시합니다.
  비활성 상태는 기존 단색 윤곽선입니다.

- 스페이스바 미리보기를 닫은 뒤 파일 목록에 남던 점선 포커스 표시를 제거했습니다.
  선택 상태와 키보드 조작은 유지합니다.

이후 변경도 사용자가 배포를 요청했을 때만 새 버전으로 게시합니다.

## 로컬 개발용 확인 (아직 배포하지 않은 변경)

- `./scripts/Start-Development.ps1`은 테스트 후 사용할 개발용 실행본을
  `src/ExternalDrivePanel/bin/publish-development`에 만들고 실행합니다.
  이후에는 개발용 인스턴스만 정상 종료 요청 → 빌드 갱신 → 재실행하며, 작업 중이면 종료 완료를 기다립니다.
- 헤더와 트레이에 **개발용**을 표시합니다. 정식 설치 파일과 공개 릴리스는 변경하지 않습니다.
  자동 업데이트와 자동실행 설정 변경은 개발용에서 사용하지 않습니다.
- 이 컴퓨터에서 개발용을 Windows 시작 시 실행하려면 `./scripts/Start-Development.ps1 -RegisterStartup`을 사용합니다.
  기존 사용자 자동실행 항목을 개발용으로 교체하며, 이전 값은 개발용 설정 폴더의
  `startup-registration-backup.json`에 한 번 백업합니다. 개발용 설정창의 자동실행 옵션은 계속 비활성화됩니다.
- 설정은 `%APPDATA%/ExternalDeskPanel-Development/config.json`에 분리합니다.
  처음 실행할 때만 정식 버전의 설정·등록·즐겨찾기를 복사하며 이후 양쪽 설정은 독립적입니다.
  실제 드라이브 파일에 대한 복사·이동·삭제 동작은 평소와 같습니다.
- 다시 열 때는 `dist/ExternalDrivePanel-Development.lnk`를 사용합니다.
  정식 버전은 트레이에서 종료하고 한 종류만 실행해 중복 패널과 드라이브 감시를 피하세요.
- 개발 중인 세로 배치는 헤더·툴바·주소줄과 현재 화면의 실제 표시 행 수에 필요한 높이를 먼저 계산합니다.
  설정 → **패널 크기 배분**에서 **균등 분할 (고정)** 또는 **내용에 따라 자동**을 선택할 수 있습니다.
  선택 즉시 반영되고 저장되며, 취소하면 창을 열기 전 선택으로 돌아갑니다. 기존 설정은 자동 배분을 유지합니다.
  균등 모드는 항목 수와 무관하게 등분하고 패널 사이 경계 조절을 막습니다. 전체 영역 크기 조절은 유지합니다.
  아이콘 크기·패널 폭·모니터 배율과 상세보기의 열 제목도 반영합니다.
  상세 목록의 행과 열 제목은 화면과 높이 계산이 같은 24 DIP 기준을 공유해 과도한 여백 계산을 막습니다.
  남는 높이도 실제 항목 표시 높이에 비례해 배분하므로, 각 패널의 내용 대비 여백 비율이 같아집니다.
  즐겨찾기 홈에서는 즐겨찾기 수, 폴더 안에서는 숨김 설정을 반영한 현재 폴더의 표시 항목 수를 사용합니다.
  폴더 이동·뒤로/앞으로·홈 복귀와 기존 파일 감시를 통한 추가/삭제 새로고침에도 자동으로 반영됩니다.
  검색 화면은 검색 결과 수를 기준으로 배분하며, 검색 진행·완료·결과 없음과 원래 화면 복귀에도 반영합니다.
  검색 상태 안내줄이 차지하는 높이도 포함합니다. 기존 검색 진행 알림을 활용하고 별도 스캔·상시 타이머는 추가하지 않습니다.
  공간이 부족하면 가능한 범위에서 각 패널의 한 행을 우선 확보하고 남은 높이를 추가 행에 배분합니다.
  모두 비어 있으면 균등 분할하며, 영역이 너무 작으면 최소 높이도 함께 줄여 영역 안에 맞춥니다.
  표시 항목 수·연결 패널·보기 크기/모드·배율·화면 영역 설정이 바뀌면 다시 배분합니다.
  자동 모드에서는 그 외에 직접 조정한 높이와 크기를 유지합니다. 자동 배분은 세로 나열에 적용되며 가로 나열은 균등합니다.
- 패널의 스크롤바는 8 DIP 폭의 둥근 막대로 표시합니다. 가로 스크롤도 같은 두께를 쓰며 휠·드래그·페이지 이동은 유지합니다.
- 메인 헤더의 설정과 미리보기 사이 **새로고침**은 드라이브 목록을 다시 확인합니다.
  Windows Code 47(안전 제거 대기) USBSTOR/UASP 저장장치를 찾으면 관리자 권한 확인 후 해당 USB 포트만 재연결을 시도합니다.
  장치/포트 식별을 다시 검증하며 활성 디스크가 남은 포트, 복합 장치, 허브·컨트롤러·도크는 대상으로 삼지 않습니다.
  일반 새로고침에는 권한 요청이 없고, 정상 사용 중인 장치를 비활성화하거나 허브 전체를 재시작하지 않습니다.
  장치·드라이버가 지원하지 않는 경우 케이블을 다시 연결해야 합니다. 요청 성공과 실제 드라이브 감지를 구분해 안내합니다.
  실제 포트 전원 재연결과 UAC 승인은 자동 테스트에서 실행하지 않습니다. 읽기 전용 조회와 가짜 플랫폼으로 검증합니다.

### 현재 공개 설치본

GitHub Releases의 `ExternalDrivePanel-win-Setup.exe`를 실행하면 현재 사용자 계정에 설치됩니다.
관리자 권한 없이 `%LOCALAPPDATA%\ExternalDrivePanel`에 설치하고 바탕화면/시작 메뉴 바로가기를 만듭니다.
Windows 설정의 설치된 앱 목록에서 제거할 수 있습니다. 설정은 `%APPDATA%\ExternalDeskPanel`에 유지됩니다.
시작프로그램은 기본으로 켜지지 않으며 메인헤더의 설정 → **Windows 시작 시 자동 실행**으로 선택합니다.
취소는 원래 상태로 되돌리고 닫기는 선택을 유지합니다. Windows 작업 관리자에서 사용자가
시작프로그램을 별도 비활성화한 경우에는 그 Windows 설정도 확인하세요.

설치본은 시작 20초 후 및 6시간마다 공개 GitHub Releases를 확인합니다. 새 버전을 백그라운드로
내려받고, 전체 패널 하단에 **업데이트 후 다시 시작** 버튼을 표시합니다. 파일 목록을 가리지 않도록
안내 영역을 따로 확보합니다. 버튼 클릭 → 확인 → 진행 중인 파일 작업 완료 대기 → 설정 저장 →
업데이트 → 자동 재실행 순서입니다. 사용자가 취소하거나 누르지 않으면 기존 버전을 계속 사용합니다.
일반 트레이 종료에서는 업데이트하지 않으며, 다음 실행 때 준비된 업데이트를 다시 안내합니다.
설정 저장/업데이트 시작 실패 시 앱을 유지하고 오류를 안내해 다시 시도할 수 있습니다.
오프라인/다운로드 실패 시 기존 버전을 계속 사용하며, 다음 확인 때 다시 시도합니다.
기존 1.0.1 사용자는 이번 1.0.2만 이전 방식(다운로드 알림 후 트레이 종료·다시 실행)으로 받습니다.
ZIP/개발 실행본은 자동 업데이트하지 않습니다. 기존 ZIP 사용자는 최초 한 번 설치본으로 전환해야 합니다.
다운로드 파일에는 개인 설정이나 GitHub 토큰을 포함하지 않습니다.

```powershell
./scripts/Publish-Installer.ps1
```

결과: `dist/releases/<버전>`의 Setup.exe, full.nupkg, `releases.win.json`, 체크섬입니다.
설치 EXE만 사용자에게 전달해도 됩니다. 단 **업데이트 제공을 위해 GitHub Release에는 피드와 nupkg도 함께 게시**해야 합니다.
미서명 무료 배포본이므로 SmartScreen/백신의 평판 경고가 나타날 수 있습니다.

향후 배포 순서: csproj의 Version 증가 → 검증 → 커밋/푸시 → 해당 버전의 `v1.0.3` 같은 태그 푸시.
`.github/workflows/release.yml`이 Windows에서 로직 검사·빌드·패키징 후 GitHub Release를 만듭니다.
커밋/푸시만으로 사용자 앱이 바뀌지는 않습니다. 새 버전 Release 게시가 필요합니다.
이미 게시한 버전을 덮어쓰지 말고 패치 버전을 올리세요. 첫 공개 전 라이선스/민감정보 검토가 필요합니다.
실제 WPF/다중 모니터 smoke는 로컬 Windows에서 실행하며, Actions에서는 화면 없는 로직 검사를 실행합니다.
설치 파일 게시 전 Actions의 임시 Windows 사용자 환경에서 이전 공개 설치본 → 새 버전의 실제
업데이트·자동 재시작·설정/즐겨찾기 유지와 새 설치·설치된 앱 등록·제거를 검사합니다.

이전 Python 버전은 [`python-legacy/`](python-legacy/) 폴더에 보관되어 있습니다.


## 배포 준비본 빌드 및 검증

.NET 10 SDK(10.0.400 이상 같은 feature band의 최신 패치)와 Windows가 필요합니다.
현재 실제 검증 대상은 Windows 11 x64입니다. API 최소 기준(Windows 10 1809)과
런타임의 공식 지원 OS는 다르므로 [Microsoft 지원 목록](https://github.com/dotnet/core/blob/main/release-notes/10.0/supported-os.md)을 확인하세요.
공개 배포 전에 새 런타임 보안 패치가 나왔는지 확인하고 Portable 프로필과 라이선스 수집 버전을 함께 갱신하세요.
포터블 프로필은 .NET / WPF 런타임 10.0.13을 포함하며 트리밍은 사용하지 않습니다.
압축된 EXE와 함께 있는 DLL/라이선스 파일을 모두 유지해야 합니다. EXE 하나만 복사해 배포하지 마세요.

```powershell
dotnet build -c Release
./scripts/Test-All.ps1
# 현재 클립보드를 변경해도 되는 테스트 환경에서만:
./scripts/Test-All.ps1 -IncludeClipboard
# 먼저 트레이의 종료로 정상 종료한 뒤:
./scripts/Publish-Portable.ps1
# 실행 중인 테스트 앱을 강제 종료해도 되는 경우에만 -StopRunning 사용.
./scripts/Publish-Portable.ps1 -StopRunning -Restart
```

출력 폴더는 `src/ExternalDrivePanel/bin/publish-latest` 하나이며,
`dist/ExternalDrivePanel-<버전>-win-x64.zip`과 SHA-256 검증 파일을 생성합니다.
최종 ZIP은 포함된 DLL/라이선스와 함께 새 폴더에 풀고 EXE를 실행합니다.
이전 publish 폴더는 자동 삭제하지 않습니다. 설정과 사용자 파일은 배포물에 넣지 않습니다.
서명되지 않은 개인 배포본이므로 Windows의 평판 기반 경고가 나타날 수 있습니다.
실행 중 덮어쓰기보다는 앱을 정상 종료한 뒤 배포본을 교체하세요.

### 안정성 및 성능 정리

- 같은 설정 경로를 사용하는 앱은 한 번만 실행됩니다. 종료/강제 종료 후 OS가 잠금을 회수합니다.
  PDF/볼륨 이름 변경 보조 모드는 별도로 동작하며 메인 앱 잠금을 요청하지 않습니다.
- 설정은 UI 스레드에서 스냅샷을 만들고 백그라운드에서 순서대로 원자적으로 저장합니다.
  정상 종료 시 마지막 저장까지 기다립니다. 기존 version 1 설정을 그대로 읽습니다.
- 복사/이동/삭제/이름 변경/새로 만들기/패널 ZIP 작업을 추적합니다. 종료·꺼내기 준비 중에는
  새 쓰기 작업을 막고, 기존 작업이 있으면 사용자 확인 후 완료를 기다립니다. 강제 종료나
  전원 차단을 안전하게 만드는 기능은 아니며, 외부 앱에서 진행하는 파일 작업은 추적하지 않습니다.
- 2초 주기의 실제 드라이브 조회를 백그라운드로 옮기고 중복 폴링과 오래된 결과 적용을 막았습니다.
  최초 시작과 트레이 수동 갱신은 여전히 동기 조회이므로 응답이 느린 장치는 지연될 수 있습니다.
- 열거 시 얻은 파일 정보를 재사용하며, 선택 없는 목록 전체 순회·주기적 선택 파일 조회·
  같은 수의 검색 결과 재정렬·같은 썸네일 요청·같은 드롭 강조 재생성을 줄였습니다.
- 즐겨찾기 일괄 변경은 목록/저장 알림을 모아 처리합니다. 파일 감시 이벤트는 디스패치 요청을
  합치고 한 번에 최대 256건씩 처리하며, 감시 버퍼 오류 후 즐겨찾기를 다시 확인합니다.
- 아이콘 목록 가상화와 전체 창 통합은 드래그 선택/배치 동작을 크게 바꾸므로 이번 정리에서 제외했습니다.
  아주 큰 폴더의 최초 열기·아이콘 생성은 여전히 느릴 수 있습니다.
- 리사이즈 중 일부 환경의 시각적 떨림은 알려진 제한입니다. 좌표 테스트 통과를 떨림 해결로 간주하지 않습니다.
  화면보다 넓게 늘릴 때 Windows의 기본 최대 추적 크기로 반대쪽 가장자리가 잘리던 오류는
  요청한 물리 크기에 맞게 제한을 보정해 해결했습니다. 별도의 지연 리사이즈/윤곽선 알고리즘은 사용하지 않습니다.

`ReadinessSmoke`는 별도 프로세스의 중복 실행 방지/잠금 해제, 연속 저장 스냅샷,
소스·대상 경로별 작업 추적과 종료 대기, ZIP 실패 시 추적 해제, 즐겨찾기 일괄 알림을 검증합니다.
기본 일괄 실행은 모든 테스트 프로젝트를 실행하되 클립보드를 변경하는 검사만 제외합니다.
클립보드 검사까지 실행하려면 명시적으로 선택할 수 있습니다.

## 드라이브 전체 검색

각 패널의 파일 도구줄에서 휴지통 오른쪽 검색창에 입력하고 Enter 또는 돋보기를 누릅니다.
검색창은 도구 버튼을 제외한 남은 폭을 사용하며, Ctrl+F로 바로 포커스할 수 있습니다.
파일 작업 버튼은 기존의 34px 폭/간격을 유지하며, 검색 돋보기도 같은 22px 벡터 아이콘을 씁니다.
크기 조절 때 버튼 크기나 리소스를 반복 변경하지 않고 검색창만 남은 폭에 맞춥니다.
파일/폴더 이름 일부(대소문자 무시), `*.pdf`/`photo?.jpg` 패턴, `.jpg` 또는 `ext:jpg`를 지원합니다.
현재 폴더나 즐겨찾기에 한정하지 않고 해당 드라이브 전체를 검색합니다. 파일 내용, Windows
검색의 고급 조건식/색인은 지원하지 않습니다. 큰 드라이브의 첫 검색은 시간이 걸릴 수 있습니다.

검색은 백그라운드에서 실행하며 중간 결과와 진행 수를 표시합니다. 숨김 표시 옵션을 따르고,
접근할 수 없는 경로와 재분석 지점(심볼릭 링크/연결 지점)은 건너뜁니다. 결과는 최대 5,000개이며
제한에 도달하면 검색어를 좁히도록 안내합니다. 중지 버튼은 현재 결과를 유지하며 검색만 중단합니다.
X/검색어 지우기/Esc/뒤로 버튼은 검색 전 화면으로 복귀하고, 홈/드라이브 이름/결과 폴더를 누르면
해당 화면으로 이동합니다. 이전 검색의 늦은 결과는 새 검색이나 이동한 화면을 덮어쓰지 않습니다.

아이콘/상세 보기, 다중 선택, 우클릭, 즐겨찾기 추가와 스페이스바 미리보기를 그대로 사용합니다.
상세 검색에는 ‘위치’ 컬럼을 추가하며 선택/툴팁으로 실제 전체 경로를 확인할 수 있습니다.
검색 결과의 빈 공간에는 복사 대상 폴더가 없으므로 붙여넣기/새로 만들기를 비활성화합니다.
검색어와 결과는 설정에 저장하지 않습니다. 꺼내기/창 닫기 시 검색을 취소합니다.

`dotnet run --project tests/DriveSearchSmoke -c Release`는 임시 파일로 이름/확장자/재귀 검색,
취소/결과 제한과 모니터별 300/360/480/760px 검색창 배치, 화면 전환과 지연 결과 무시를 검사합니다.

각 드라이브 헤더 바로 아래에는 24 물리 픽셀 높이의 용량 바를 표시합니다. 전체 크기/사용 가능
공간/사용률을 바 안에 표시하며, 사용률이 80%를 넘으면 파란색 대신 붉은색을 사용합니다.
용량은 파일 전체를 순회하지 않고 Windows의 볼륨 정보로 읽고, 10초마다 및 패널 파일 작업 후
백그라운드에서 갱신합니다. 읽을 수 없는 경우 팝업 대신 바 안에 안내합니다. 바는 애니메이션 없이
패널 폭에 반응하며, 모니터 배율이 달라도 같은 물리 높이를 유지합니다.
`dotnet run --project tests/VolumeCapacitySmoke -c Release`로 경계값·실제 용량 조회·모니터별 배치를 검사합니다.

## 스페이스바 파일 미리보기 (Windows 10 1809 이상 / Windows 11)

항목을 선택하고 Space를 누르면 원본을 바꾸지 않는 전용 미리보기 창을 엽니다.
즐겨찾기/폴더, 아이콘/상세 보기 모두 동일합니다. Esc 또는 Space로 닫고,
↑/↓ 또는 상단 항목 버튼으로 파일을 넘깁니다(텍스트 입력 영역에서는 화살표로 글을 탐색).
여러 항목을 선택한 경우 그 항목들 사이에서만 이동합니다. 창을 열어둔 채 패널의
선택을 바꾸면 새 선택을 표시하며, 드라이브 패널을 닫으면 미리보기도 정리합니다.

- PDF: Windows.Data.Pdf 내장 엔진, 페이지 이동(←/→), 확대/축소, 창에 맞춤.
- 이미지: JPG/PNG/BMP/GIF/TIFF/ICO 등 WPF/Windows 코덱으로 지원되는 형식.
  GIF/TIFF는 첫 프레임이며 HEIC/WebP/AVIF 등은 설치 코덱에 따라 달라집니다.
- 텍스트·코드·CSV·JSON·XML 등: 읽기 전용, UTF-8/UTF-16 BOM/한국어 CP949,
  최대 앞부분 128KB. HTML/스크립트/SVG는 실행하지 않고 소스 글자로만 표시합니다.
- 음성·영상: WPF MediaElement/Windows 코덱으로 지원되는 MP3/WAV/MP4 등.
  자동 재생하지 않으며, 재생/일시정지는 버튼으로 선택합니다.
- 기타: Windows 썸네일이 있으면 이를 표시하고, 없으면 기본 정보만 표시합니다.
  Office 문서 전체 열람, 암호 PDF 입력, 미지원 코덱 등은 ‘기본 앱으로 열기’를 사용합니다.

외부 브라우저/WebView2/PDF 프로그램을 설치하거나 자동 실행하지 않습니다.
PDF는 같은 실행 파일의 일반 권한 보조 모드에서 Windows 엔진으로 처리합니다. 화면 없는
프로세스와 표준 입출력 파이프로 이미지만 주고받아 PDF/GPU 네이티브 수명 문제가 패널까지
전파되지 않게 격리합니다. 보조 모드는 설정/트레이/임시 결과 파일을 만들지 않으며,
닫기/꺼내기 시 정상 종료와 파일 해제를 기다리고 응답이 없으면 해당 보조 프로세스만 종료합니다.
PDF는 최대 512MB, 이미지는 최대 256MB/1억 픽셀로 제한하며 렌더링 결과는
최대 2048px로 제한합니다. 읽기/렌더링은 비동기이고 파일 전환·닫기 시 취소/해제합니다.
목록 썸네일 버튼(`globalView.showPreviews`)과는 독립된 기능입니다.
Windows Runtime API 참조를 위해 앱과 테스트의 빌드 대상을 `net10.0-windows10.0.17763.0`로 맞췄습니다.

```powershell
dotnet run --project tests/QuickPreviewSmoke -c Release
dotnet run --project tests/QuickPreviewSmoke -c Release -- --interactive
```

테스트는 임시 이미지/PDF/텍스트/무음 WAV만 사용하며 실제 사용자 파일이나 설정은 변경하지 않습니다.

## 항목 우클릭 메뉴 테스트 (Windows / .NET 10 SDK)

```powershell
dotnet run --project tests/ItemMenuLogicSmoke -c Release
dotnet run --project tests/ItemMenuSmoke -c Release
dotnet run --project tests/WindowsShellSmoke -c Release
```

첫 테스트는 메뉴 조합·확장자·즐겨찾기 경로 비교·ZIP 생성/충돌/실패 정리를,
둘째는 실제 WPF 창에서 네 가지 화면의 공통 메뉴·선택·단축키·ZIP 알림/갱신을 검사합니다.
`dotnet run --project tests/ItemMenuSmoke -c Release -- --interactive`는 사용자 설정을
읽거나 저장하지 않는 임시 패널을 띄웁니다. 여기서 실제 속성 창, 연결 프로그램,
우클릭 메뉴와 단축키를 수동 확인할 수 있습니다. 창을 닫으면 테스트 파일도 정리됩니다.

앱 선택은 `ShellExecuteEx(openas)`를 먼저 사용하며, 해당 동사가 지원되지 않는
환경의 `ERROR_NO_ASSOCIATION`에 한해 `SHOpenWithDialog`로 대체합니다.
ZIP은 일반 파일/폴더를 지원하며, 링크/연결 지점은 재귀 순환 방지를 위해 안내 후 중단합니다.

빈 공간에서 드래그하면 사각형으로 여러 항목을 선택할 수 있습니다. Ctrl/Shift 클릭과

공유 UI는 해당 명령이 제공되는 파일에만 사용 가능하며, 전송은 사용자가 직접 선택해야 합니다.
네이티브 메뉴와 공유 UI는 HWND 소유 STA에서 호출하며, 설치된 셸 확장의 동작/응답성은 OS·확장에 따릅니다.
파일 변경 감시로 외부/비동기 셸 작업 후 현재 목록을 갱신합니다.

시작할 때는 설정창을 만들지 않으며, 창을 표시하기 전에 물리 좌표 배치를 준비합니다.
첫 렌더까지 초기 배치를 유지해 혼합 DPI 환경에서 기본 크기의 큰 창이 잠깐 보이지 않도록 했습니다.
`SettingsWindowSmoke`는 두 모니터의 첫 native SHOWWINDOW 크기와 설정창 재배치를,
`RegistrationSmoke`는 시작 중 설정창이 한 번도 로드되지 않는 것을 검사합니다.
`WindowsShellSmoke -- --interactive`는 실제 셸 메뉴와 새 도구줄을 확인할 격리된 임시 패널입니다.
자동 테스트는 임시 파일에서 메뉴 생성/반복 취소, 클립보드, 복사/이동/이름 변경/생성,
파일 감시를 검사하며 실제 삭제·공유 전송·바탕화면 변경은 실행하지 않습니다.
